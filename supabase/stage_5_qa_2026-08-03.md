Дата: 2026-08-03

## Статус

**Pass with residual risk.** Cohort isolation and build checks passed. Release still requires one authenticated browser pass with real student, expert and admin sessions.

## Backend and RLS verification

Проверки выполнены через Supabase MCP в read-only транзакциях с role simulation:

- student flow 1 видит только flow 1;
- student flow 1 не видит flow 2 settings, materials, progress или gamification;
- `can_access_cohort('flow-2')` для student возвращает `false`;
- `get_available_cohorts()` для student возвращает только один доступный поток;
- privileged role видит оба потока и настройки flow 2;
- flow 2 имеет 0 опубликованных материалов, 0 персонального прогресса, 0 gamification rows, 0 visits, 0 submissions, 0 votes и 0 notifications;
- flow 2 schedule rows существуют как нейтральные settings, но не доступны student и не содержат опубликованных дат;
- direct leaderboard request для student к flow 2 возвращает 0 строк;
- direct `increment_points` execution для `authenticated` закрыт.

## Security fix during QA

Найдена и исправлена возможность прямого начисления баллов через `increment_points`.

Добавлена миграция `012_guard_agent_launch_points`:

- новый `record_agent_launch(p_cohort_id)` проверяет доступ, сам вычисляет week number и начисляет фиксированные 5 points;
- клиент больше не вызывает `increment_points` напрямую;
- `increment_points` закрыт для `public`, `anon` и `authenticated`.

Оставшиеся Supabase security advisor warnings относятся к intentionally client-callable guarded `SECURITY DEFINER` RPC и общей legacy Auth configuration. Они требуют отдельного security cleanup, но не отменяют cohort isolation gate.
